# セキュアなPHP CRUDアプリ

PHP（PDO）とMariaDBを使用して構築した、セキュリティ意識（ディレクトリ分離、`.env` による機密情報管理）を取り入れたシンプルなCRUDアプリケーションです。

## 🛡️ こだわりのポイント
- **セキュアなディレクトリ構造**: Webサーバーの公開ルート（`public/`）と、ロジック・設定ファイル群を分離し、機密情報の露出を防止。
- **環境変数の利用**: データベースの接続情報などを `.env` で管理し、Git管理から除外（`.gitignore`）。
- **堅牢なデータベース設計**: `NOT NULL` 制約や自動日時記録（`TIMESTAMP`）を活用。

## 📁 ディレクトリ構成
```text
my-crud-app/
├── inc/
│   └── db.php          # データベース接続設定・処理
├── public/              # Web公開領域（ドキュメントルート）
│   ├── delete.php      # 削除処理
│   ├── edit.php        # 編集画面および更新処理
│   ├── error_check.php # エラーチェック
│   ├── index.php       # 一覧画面（トップページ）
│   └── token_check.php # トークンチェック
├── .env                # 環境変数（DB接続情報など）
├── .gitignore          # Git管理除外設定
└── README.md           # プロジェクト説明ドキュメント
```




# 🛡️ このアプリで実装する主要なセキュリティ対策
## 1. ディレクトリ分離（Web公開ルートの制限）
仕組み: Webサーバーが外部に公開するフォルダを public/ だけにし、設定ファイルやデータベース接続ファイル（db.php や .env）はその外側（ルートディレクトリ）に置く。

効果: 万が一Webサーバーの設定が甘くても、URLから直接 .env や重要ファイルを覗き見られるリスクを物理的にシャットアウトします。

## 2. 機密情報のハードコーディング防止（.env の活用）
仕組み: データベースのパスワードや接続情報をソースコードに直接書かず、.env ファイルに分離して管理する。さらにそれを .gitignore でGitの管理から除外する。

効果: GitHubなどのリモートリポジトリにソースコードを公開しても、パスワードが外部に流出する事故を防ぎます。

## 3. SQLインジェクションの完全防止（PDO ＆ プレペアドステートメント）
仕組み: ユーザーが入力したデータとSQLの命令を完全に分離する「プレースホルダー（?）」を使用する。さらに、PHP側の偽装（エミュレーション）をオフ（PDO::ATTR_EMULATE_PREPARES => false）にして、データベース本家の安全な仕組みを強制する。

効果: 悪意のあるSQL文をフォームから流し込まれても、データベースが「ただの文字データ」として扱うため、データの改ざんや破壊を完全に防ぎます。

## 4. データベース制約によるデータの守り（NOT NULL）
仕組み: テーブル設計の段階で、名前や価格などの重要な項目に NOT NULL 制約をつける。

効果: プログラム側でうっかり空データや不正なデータが送られてきても、データベースが水際でブロックし、アプリのバグやクラッシュを防ぎます。

## 5. 【今後実装予定】画面表示時のセキュリティ（XSS・CSRF対策）
これから作る画面側（public/index.php など）でも、以下の対策を順次取り入れていきます！

XSS（クロスサイト・スクリプティング）対策: 画面にデータを表示するときに htmlspecialchars() を使って、悪意のあるJavaScriptタグが無効化されるようにエスケープする。

CSRF（クロスサイト・リクエスト・フォージェリ）対策: フォームからの送信に専用のトークンを持たせ、不正な外部サイトからの偽装送信をブロックする。
